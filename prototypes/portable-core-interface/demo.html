Can this contract survive the awkward cases?

This demo tests whether the proposed portable Ohdieux interface is sufficient for atomic admissions, duplicate delivery, durable retries, sticky programme failures, and separately-idempotent R2 writes—without exposing Hono or Cloudflare types.

Question being prototyped: does the combination of intent-shaped facets, read-only repositories, one atomic commit(changeSet) seam, closed outcomes, and ack | retry | discard dispositions remove implementation ambiguity? The R2 write versus halted race is intentionally left visible for human decision.

The complete declaration-only artifact is in contract.ts. The public surface stays small; orchestration remains behind it.

interface Ohdieux {
  feeds: { read(input: ReadFeed): Promise<FeedOutcome> };
  media: {
    readImage(input: ReadImage): Promise<ImageOutcome>;
    readAudio(input: ReadAudio): Promise<AudioOutcome>;
  };
  administration: Administration;
  schedule: { hourly(input: HourlyTick): Promise<ScheduleOutcome> };
  jobs: { consume(envelope: unknown): Promise<JobDisposition> };
}

type JobDisposition =
  | { kind: "ack"; reason: AckReason }
  | { kind: "retry"; failure: RuntimeFailure }
  | { kind: "discard"; diagnostic: ClassifiedCondition };
